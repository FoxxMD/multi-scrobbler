Self-Hosted Docs

Multi-Scrobbler's docs are at docs.multi-scrobbler.app but they are also generated and hosted on your instance.

If you are using a subpath and need these self-hosted docs as well you will need to build your own docker image. This is a limitation of Docusaurus, the framework the docs are built on.

This build step is optional and not required for MS to run with a subpath, you just won't have self-hosted docs and will need to use the official, hosted docs instead.

To build MS with self-hosted docs, provide the same BASE_URL used above as a build arg:

Set the timezone for the container using the environmental variable TZ.

If you are running this container with Docker on a Linux Host you should specify user:group permissions of the user who owns the configuration and data directories on the host to avoid docker file permission problems. These can be specified using the environmental variables PUID and PGID.

To get the UID and GID for the current user run these commands from a terminal:

  • id -u -- prints UID
  • id -g -- prints GID

Nodejs​

Persistent Directories​

The directories MS uses for

  • Configuration - config.json, jellyfin.json, etc...
  • Data - database, cache, etc...
  • Logs

can be specified by environmental variables passed directly to npm/node, or set in an .env file in the working directory.

Settings these paths is optional. If you do not set paths MS will try to use OS-standardized directories, falling back to subfolders in the working directory (.config/). Note: These paths are automatically set for you when using Docker.

Relative and Absolute Paths Only

When parsing these ENVs MS will resolve relative directories but not bash expansions like ~ for home. Examples:

  • CONFIG_DIR=/my/absolute/path => sets directory to use for config files
  • DATA_DIR=./relative/data => sets directory relative to working directory for data files
  • LOGS_DIR=~/myDir/logs => ❌ cannot use this path!

(The bash expansions shown below are for example only)

  • Config
  • Data
  • Logs

All of your configuration files, like config.json, jellyfin.json, etc... will be read from this directory.

Order of path acquisition:

  • $CONFIG_DIR - user-defined (or auto defined in Docker image)
  • $CONFIGURATION_DIRECTORY - defined by systemd
  • OS-standardized directory from below...
  • Linux
  • MacOS
  • Windows

$XDG_CONFIG_HOME/multi-scrobbler or ~/.config/multi-scrobbler

~/Library/Preferences/multi-scrobbler

%APPDATA%\multi-scrobbler\Config

All of the persistent data -- like the database (ms.db), cache, and credential files -- will be written to this directory.

Order of path acquisition:

  • $DATA_DIR - user-defined (or auto defined in Docker image)
  • $STATE_DIRECTORY - defined by systemd
  • OS-standardized directory from below...
  • Linux
  • MacOS
  • Windows

$XDG_DATA_HOME/multi-scrobbler or ~/.local/share/multi-scrobbler

~/Library/Application Support/multi-scrobbler

%LOCALAPPDATA%\multi-scrobbler\Data

Logs will be written to this directory.

Order of path acquisition:

  • $LOGS_DIR - user-defined (or auto defined in Docker image)
  • $LOGS_DIRECTORY - defined by systemd
  • OS-standardized directory from below...
  • Linux
  • MacOS
  • Windows

~/Library/Logs/multi-scrobbler

%LOCALAPPDATA%\multi-scrobbler\Log

Reverse Proxy Recommended​

Multi-Scrobbler's UI performs best when it is behind a reverse proxy, like NGINX (NPM) Traefik or Caddy.

Why: Security

Most reverse proxies have easy ways to set up basic authentication which a necessity if you plan on running Multi-Scrobbler on a machine directly exposed to the internet.

Why: Connection Pooling and Live Events

For connections to domains using HTTP/1.1 (non-TLS http: addresses like http://192.168.0.101) all major browsers use a shared connection pool per domain, that is used across all tabs. This connection pool is limited to 6 concurrent connections.

For non-TLS connections Multi-Scrobbler uses one, always-open SSE connection per tab to send live updates and logs to your browser.

So, with HTTP/1.1, if you open more than 5 tabs of multi-scrobbler you will not be able to communciate to the server through your browser.

Using TLS (like https://ms.mydomain.com), which reverse proxies make easy, removes this connection limit for the pool.

Additionally, using TLS unlocks the ability for Multi-Scrobbler to share a single SSE connection between all tabs which reduces the bandwidth used by all tabs signficantly.

Disable Buffering for Searches

When Multi-Scrobbler performs metadata searches for your Play data it streams results from providers as soon as they arrive, rather than waiting for all providers to respond. This can significantly speed up how soon you see search results in your browser.

Some reverse proxies automatically enable buffering for requests which is usually a good thing but in this scenario prevents you from benefiting streaming results because buffering waits for the entire response before forwarding it to your browser.

Use one of the common methods below to disable buffering for search-related routes. Note: these are not complete solutions, just examples as a jumping off point:

  • Caddy
  • nginx
  • Traefik

Set flush_interval -1 to disable response buffering.

NGINX

Traefik does not automatically enable buffering. If you use the Buffering middleware then responses are automatically buffered and cannot be disabled, yet.
