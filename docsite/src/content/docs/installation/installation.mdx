### Recommended Settings

<Tabs groupId="dockerSetting" queryString>
<TabItem value="storage" label="Storage">
You **should** bind a host directory into the container for storing configurations, credentials, database, and other files. Otherwise, these will be lost when the container is updated.

<Aside type="important">

You should create these folders on the host **before** starting Multi-Scrobbler for the first time.

</Aside>

```yaml title="docker-compose.yml"
services:
  multi-scrobbler:
  # ...
  # [!code highlight:2]
  volumes:
    - "./config:/config" #[!ref] Mounts the host directory `./config` into the container at `/config`
```

<DetailsAdmo type="note" summary="Optional Data Directory">

Optionally, use a separate directory for data (database, cache, etc...) by mounting an additional directory and setting the `DATA_DIR` ENV to the directory that should be used inside the container:

```yaml title="docker-compose.yml"
services:
  multi-scrobbler:
  # ...
  # [!code focus:7]
  environment:
    # ...
    # [!code highlight]
    - DATA_DIR=/msData #[!ref] Tells MS where to look for the data directory, inside the container
  volumes:
    - "./config:/config"
  # [!code highlight]
    - "./data:/msData" # [!ref] Mounts the host directory `./data` into the container at `/msData`
```

</DetailsAdmo>

</TabItem>
<TabItem value="networking" label="Networking">
If you are using a [bridge network](https://www.appsdeveloperblog.com/docker-networking-bridging-host-and-overlay/) (default docker setup) you must map a port to the container in order to access the dashboard and use MS with [Ingress Sources](/configuration/sources/#by-communication-method) like the Listenbrainz Endpoint.

The default container port is `9078`.

```yaml title="docker-compose.yml"
services:
  multi-scrobbler:
  # ...
  # [!code highlight:2]
  ports:
    - "9078:9078"
```

<Aside type="important">

**Read [Securing Multi-Scrobbler](/security/overview)**

<TabItem value="baseUrl" label="Base URL">

The [**Base URL**](/configuration/#base-url) is an **optional** value you can provide to Multi-Scrobbler to let it know what URL it will be accessible from.

Providing this value has [many benefits](/configuration#base-url), it is highly recommended that you set it.

<Badge text="Tip" size="small" variant="success" /> The **Base URL** value is an interactive placeholder. Fill it in to update its usage everywhere on this site.

<Tabs groupId="baseUrlUsage">
<TabItem value="redirect" label="Redirects">
When using a [Source or Client](/configuration/) that has a "Redirect URI" that you have not explicitly defined, setting the Base URL allows correct redirect URLs to be generated automatically.

```yaml title="docker-compose.yml" placeholder="http://YOUR_MS_DOMAIN:9078"
services:
  multi-scrobbler:
  # ...
  environment:
    # [!code highlight:1]
    - BASE_URL=http://YOUR_MS_DOMAIN:9078 # [!ref] Should be the same URL you would use to view the MS dashboard in a browser
```

`BASE_URL` is also used when [Securing Your Instance](/security/authentication/#unsecured-instance-protections).

</TabItem>
<TabItem value="subpath" label="Deploying MS with a Subpath">
When deploying MS to a domain where it will be served under a **subpath** like

```text placeholder="YOUR_MS_DOMAIN.com/multiscrobbler"
https://YOUR_MS_DOMAIN.com/multiscrobbler
```

you **must** define `BASE_URL` in order for MS to properly serve the dashboard:

```yaml title="docker-compose.yml" placeholder="YOUR_MS_DOMAIN.com/multiscrobbler"
services:
  multi-scrobbler:
    # ...
    environment:
      # [!code highlight:1]
      - BASE_URL=https://YOUR_MS_DOMAIN.com/multiscrobbler # [!ref] multi-scrobbler served under this subpath
```

This is **not required** when the root path is `/`, like `https://my-scrobbler.com` or `scrobbler.mydomain.com`.

<DetailsAdmo type="important" summary="Self-Hosted Docs">

Multi-Scrobbler's docs are at [docs.multi-scrobbler.app](https://docs.multi-scrobbler.app/) but they are also generated and hosted on your instance.

If you are using a **subpath** and need these self-hosted docs as well you will need to **build your own docker image.** This is a limitation of Docusaurus, the framework the docs are built on.

This build step is *optional* and not required for MS to run with a subpath, you just won't have self-hosted docs and will need to use the official, hosted docs instead.

To build MS with self-hosted docs, provide the same `BASE_URL` used above as a build arg:

```yaml title="docker-compose.yml" placeholder="YOUR_MS_DOMAIN.com/multiscrobbler"
services:
  multi-scrobbler:
    #image: docker.io/foxxmd/multi-scrobbler:latest [!ref] remove or comment out the official image, use `build` spec instead to point to the repository
    # [!code highlight:4]
    build:
      context: https://github.com/FoxxMD/multi-scrobbler.git
      args:
        - BASE_URL=https://YOUR_MS_DOMAIN.com/multiscrobbler # [!ref] **Must** include `BASE_URL` build arg here
    # ...
    environment:
        # ...
        # [!code highlight:1]
        - BASE_URL=https://YOUR_MS_DOMAIN.com/multiscrobbler # [!ref] multi-scrobbler served under this subpath
```

</DetailsAdmo>
</TabItem>

**Optionally**, add a [Valkey](https://valkey.io/) service to your stack for [secondary caching](/configuration#secondary-caching) to take advantage of faster performance, reduced memory usage, and cached api calls to external services.

```yaml title="docker-compose.yml"

    # ...
    environment:

    # ...

  # [!code highlight:8]
  valkey:
    image: valkey/valkey
    volumes:
      - valkeydata:/data

volumes:
  valkeydata:
    driver: local
```

<TabItem value="debug" label="Debug Image">
The default image has no shell or system tools. When troubleshooting, especially networking issues, switch to the same version with a `-debug` suffix, like `latest-debug` or `1.2.3-debug`. It is identical to the normal image but adds a [busybox](https://busybox.net/) shell and `curl`.

```yaml title="docker-compose.yml"
services:
  multi-scrobbler:
    # [!code highlight]
    image: foxxmd/multi-scrobbler:latest-debug
```

Then open a shell in the running container:

```shell
docker exec -it multi-scrobbler sh
curl -v https://example.com
```

Switch back to the normal image when you are done.

</TabItem>

### User and Permissions :badge[Important]{variant="tip"}

The container runs as a non-root user, UID/GID `65532:65532`, by default.

This user must be able to read and write the **configuration and data directories** you mount into it.

If you bind mount host directories (like `./config:/config` from the **Storage** tab above) choose **one** of these:

<Tabs groupId="userPerms">

<TabItem value="sameUser" label="Same User (Simplest)">

**Run the container as the user who owns the directory** (simplest).

In this scenario you will be able to edit and read config/db/log files used by MS normally from your host.

Get your UID and GID with `id -u` and `id -g`:

```shell placeholder="1000,1001"
$ id -u
1000
$ id -g
1001
```

Then, set [`user`](https://docs.docker.com/reference/compose-file/services/#user):

  ```yaml title="docker-compose.yml" placeholder="1000,1001"
  services:
    multi-scrobbler:
    # ...
    # [!code highlight]
    # [!code focus:1]
    user: 1000:1001
    # ...
    volumes:
      - "./config:/config"
  ```

</TabItem>
<TabItem value="unprivileged" label="Unprivileged">

**Run the container as the default user** (most isolated).

This is the most secure option as the user unlikely has any privileges on the host machine but it does mean you will need to use `sudo` to edit config files created by it.

Make sure the host folders already exist and then give the default user ownership, or permission, to create/edit these.

The easiest way to do this is give full ownership:

```shell
# [!callout /config/] existing host directory
sudo chown -R 65532:65532 ./config
```

If you have `user` set in `docker-compose.yml` then you should remove it now.

</TabItem>
</Tabs>

**Note:** The above advice also applies to Docker Desktop on Windows when the directory is inside WSL (like `~/multi-scrobbler/config`). Run the commands in your WSL terminal.

<Aside type="tip">

If you are using [named volumes](https://docs.docker.com/reference/compose-file/volumes/#example) for MS, instead of bind mounted volumes, no extra setup is needed.

</Aside>

The example scenario:

* [Jellyfin **Source**](/configuration/sources/jellyfin)
* [Maloja **Client**](/configuration/sources/maloja)

* Docker container located on a different IP (`192.168.0.100`) so use [Base URL](/configuration#base-url)

* Linux uid/gid is `1000:1000`
* Optional caching using valkey (after uncommenting)

      - TZ=Etc/GMT # Specify timezone from TZ Database name found here https://en.wikipedia.org/wiki/List_of_tz_database_time_zones

      - MALOJA_URL=http://domain.tld:42010
      - MALOJA_API_KEY=1234
      # uncomment along with valkey service/volume below for better caching
      #- CACHE_VALKEY=redis://valkey:6379
    user: 1000:1000
    volumes:
      - ./config:/config

      - 9078:9078

### Nodejs

Clone this repository somewhere using the latest [git tag](/updating#git) and then install from the working directory.

```shell placeholder="<LATEST_RELEASE_TAG>"
git clone --branch <LATEST_RELEASE_TAG> https://github.com/FoxxMD/multi-scrobbler.git
cd multi-scrobbler
nvm use # [!ref] optional, to set correct Node version
npm install
npm run docs:install && npm run build
npm run start
```

Pass ENVs directly to `node`/`npm`, or make a new `.env` (using `.env.example` as a reference), to configure MS for basic settings and [**Persistent Directories**](./?#persistent-directories) for config/data/log directories.

## Persistent Directories

The directories MS uses for 

* **Configuration** - `config.json`, `jellyfin.json`, etc...
* **Data** - database, cache, etc...
* **Logs**

can be specified by environmental variables passed directly to `npm`/`node`, or set in an `.env` file in the working directory.

Settings these paths is *optional.* If you do not set paths MS will try to use OS-standardized directories, falling back to subfolders in the working directory (`.config/`). **Note: These paths are automatically set for you when using Docker.**

<DetailsAdmo type="note" summary="Relative and Absolute Paths Only">

When parsing these ENVs MS will resolve relative directories but *not* bash expansions like `~` for home. Examples:

* `CONFIG_DIR=/my/absolute/path` => sets directory to use for config files
* `DATA_DIR=./relative/data` => sets directory relative to working directory for data files
* `LOGS_DIR=~/myDir/logs` => ❌ cannot use this path!

(The bash expansions shown below are for example only)

</DetailsAdmo>

<Tabs groupId="dirType" queryString>
    <TabItem value="config" label="Config">

      All of your configuration files, like `config.json`, `jellyfin.json`, etc... will be read from this directory.

      Order of path acquisition:

      * `$CONFIG_DIR` - user-defined (or auto defined in Docker image)
      * `$CONFIGURATION_DIRECTORY` - defined by [systemd](/installation/service)
      * OS-standardized directory from below...
      
      <Tabs>
        <TabItem value="linux" label="Linux">
            `$XDG_CONFIG_HOME/multi-scrobbler` or `~/.config/multi-scrobbler`
        </TabItem>
        <TabItem value="mac" label="MacOS">

        </TabItem>
        <TabItem value="win" label="Windows">

        </TabItem>
      </Tabs>
    </TabItem>
    <TabItem value="data" label="Data">

      Order of path acquisition:

      * `$DATA_DIR` - user-defined (or auto defined in Docker image)

        </TabItem>

## Reverse Proxy Recommended

Multi-Scrobbler's UI performs best when it is behind a reverse proxy, like NGINX (NPM) Traefik or Caddy.

<details>

<summary>Why: Connection Pooling and Live Events</summary>

For connections to domains using HTTP/1.1 (non-TLS `http:` addresses like `http://192.168.0.101`) all major browsers use a [shared connection pool per domain](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Connection_management_in_HTTP_1.x#domain_sharding), that is used across *all* tabs. **This connection pool is limited to 6 concurrent connections.**

For non-TLS connections Multi-Scrobbler uses one, always-open [SSE connection](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events) **per tab** to send live updates and logs to your browser.

So, with HTTP/1.1, if you open more than 5 tabs of multi-scrobbler you will not be able to communciate to the server through your browser.

Using TLS (like `https://ms.mydomain.com`), which reverse proxies make easy, removes this connection limit for the pool.

Additionally, using TLS unlocks the ability for Multi-Scrobbler to share a *single* SSE connection between *all* tabs which reduces the bandwidth used by all tabs signficantly.

</details>

<DetailsAdmo type="tip" summary="Disable Buffering for Searches">

When Multi-Scrobbler performs [metadata searches](/configuration/editing/#search-providers) for your Play data it streams results from providers as soon as they arrive, rather than waiting for all providers to respond. This can significantly speed up how soon you see search results in your browser.

Some reverse proxies automatically enable *buffering* for requests which is usually a good thing but in this scenario prevents you from benefiting streaming results because buffering waits for the entire response before forwarding it to your browser.

Use one of the common methods below to disable buffering for search-related routes. Note: these are not complete solutions, just examples as a jumping off point:

<Tabs groupId="rp" queryString>
<TabItem value="caddy" label="Caddy">

Set [`flush_interval -1`](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming) to disable response buffering.

```Caddyfile {10}
multi-scrobbler.domain.tld {
  reverse_proxy multi-scrobbler:9078

  @search {
    method POST GET
    path /api/metadata/search/*
  }

  reverse_proxy @search multi-scrobbler:9078 {
    flush_interval -1
  }

}
```

</TabItem>
<TabItem value="NPM/NGINX" label="nginx">

<h3>NGINX</h3>

```nginx {3} placeholder="/your-route,http://your_backend"
location /your-route {
    proxy_pass http://your_backend;
    proxy_buffering off;
}
```

</TabItem>
<TabItem value="traefik" label="Traefik">

Traefik does not automatically enable buffering. If you use the [Buffering middleware](https://doc.traefik.io/traefik/reference/routing-configuration/http/middlewares/buffering/) then responses are automatically buffered and cannot be disabled, [yet.](https://github.com/traefik/traefik/issues/12869)

</TabItem>
</Tabs>
