Starting **December 1st 2026** Last.fm only gives API keys to Pro (paid) accounts. Before your key stops working, use an **Import Job** to copy your whole Last.fm scrobble history into multi-scrobbler.

Imported scrobbles are stored in multi-scrobbler's database in a **mirror**, a copy of the history of one Last.fm account. Sending imported scrobbles on to other services (ListenBrainz, Koito, etc.) will come in a later release, from the mirror. Nothing needs to be fetched from Last.fm again.

Import Jobs are under **Import Jobs** in the dashboard menu. Choose **New Import** to create one.

## Choose where to import from

You can import from the Last.fm API or from an export file.

### Last.fm API

Use this if you have a [Last.fm Client](/configuration/clients/lastfm) or [Last.fm Source](/configuration/sources/lastfm-source) that is authenticated and working. Choose **Last.fm Source/Client** and pick it.

* Scrobbles go into the mirror for that component's Last.fm account, which is created the first time.
* It is gentle with Last.fm (at most one page of 200 scrobbles per second). Large histories take a while. For example, 200,000 scrobbles take roughly half an hour.
* This only works while your API key works, so before December 1st 2026 without a Pro account.
* Libre.fm components can't be used.

### Export file

Use this if your API key no longer works, or you already have an export. These exporters are supported:

| Exporter | Format | Notes |
|---|---|---|
| [lastfm.ghan.nl](https://lastfm.ghan.nl/export/) | JSON or CSV | **Recommended.** Timestamps to the second, and MusicBrainz ids are kept. |
| [benjaminbenben](https://benjaminbenben.com/lastfm-to-csv/) | CSV | Timestamps only to the minute. See [limitations](#benjaminbenben-files). |

The format is detected automatically.

## Uploading vs the imports folder

There are two ways to give multi-scrobbler an export file.

**Upload a file** sends it from your browser. This is easiest for small to medium files (up to 2 GB). The uploaded file is deleted when the job is deleted.

**File in imports folder** uses a file you copied into the `imports` folder of the [data directory](/installation#persistent-directories) yourself. For example, with Docker and `DATA_DIR=/data` that is `/data/imports/` inside the container. Use this for very large files, or when uploads fail. Files in this folder are never deleted by multi-scrobbler. A file that another job already uses is not listed.

:::caution[Reverse proxies]

A reverse proxy in front of multi-scrobbler may refuse large uploads. For example, nginx refuses request bodies over 1 MB by default. Raise its limit for multi-scrobbler:

```nginx
client_max_body_size 2g;
```

Or place the file in the imports folder instead.

:::

## Options

* **Mirror** (files only): where the scrobbles go. Pick an existing mirror to add a newer export to it, or create a new one. If you give a new mirror a Last.fm username that an existing mirror already has, that mirror is used.
* **Range**: import everything, or only scrobbles between two dates.
* **Save raw import data**: keeps the original Last.fm data for every scrobble. It is on by default for API imports and off for files. It uses more disk space.
* **Start now**: start the import as soon as the job is created. Otherwise start it from the job's page.

## How imports work

* **Only gaps are imported.** A mirror remembers which time ranges it already has. A new import into the same mirror only fetches what is missing, and scrobbles already in the mirror are skipped. You can safely import a newer export into the same mirror later.
* **Only one import per mirror runs at a time.** Starting a second one for the same mirror is refused until the first one stops.
* **Pause, Stop, Resume.** An import keeps its position. Resume continues from where it stopped.
* **Restarts.** A running import continues by itself after multi-scrobbler restarts.
* **Errors.** When fetching from Last.fm fails, the import retries 3 times with increasing waits. If it still fails, it stops with status **Failed** and shows the error. Fix the cause, then press Resume.
* **Deleting a job** keeps the scrobbles it imported in the mirror.

## benjaminbenben files

benjaminbenben exports have timestamps only to the minute. They could not be matched reliably against data with seconds, so:

* A benjaminbenben file is always imported into **a new mirror of its own**, whatever mirror you choose.
* Several scrobbles in the same minute are all kept.

If you can, use a [lastfm.ghan.nl](https://lastfm.ghan.nl/export/) export instead.
