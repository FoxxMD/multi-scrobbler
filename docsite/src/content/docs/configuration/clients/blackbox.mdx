**Blackbox** is a generic Client that sends your scrobbles and [**Now Playing**](/configuration/clients#now-playing) activity to any URL you choose, like a webhook.

Use it to feed your own app, script, or home automation with listening activity from any of your [Sources](/configuration/sources).

<DetailsAdmo type="note" summary="One-Way Only">

For a Blackbox Client, Multi-Scrobbler only **sends** data to your endpoint.

It deliberately does not have any functions for fetching existing scrobbles from your client (for duplicate detection). This is to keep the Blackbox implementation simple.

If you need this richer functionality you are better off emulating a [Listenbrainz Client](/configuration/clients/listenbrainz). 

<Badge text="Note" size="small" variant="note" /> Blackbox **does still do [duplicate detection](/configuration/duplicates)** but only uses scrobbles Multi-Scrobbler has already sent to this Client.

</DetailsAdmo>

## Setup

Your endpoint must accept a `POST` request with a JSON body. Any `2xx` response is treated as a successful scrobble. Anything else fails the scrobble and it will be [retried later.](/configuration/clients#dead-scrobbles)

### Payload

Choose the shape of the JSON body with `payloadStyle` (or `BLACKBOX_PAYLOAD_STYLE`):

<Tabs>
<TabItem label="ms (default)">

Multi-Scrobbler's own Play shape:

```json5
{
  "type": "scrobble", // or "nowPlaying"
  "play": { /* Multi-Scrobbler Play data */ }
}
```

When Now Playing stops, a `nowPlaying` payload is sent with `"play": null`.

</TabItem>
<TabItem label="listenbrainz">

The same payload as the [ListenBrainz submit listens API.](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html#post--1-submit-listens)

Scrobbles use `"listen_type": "single"` and Now Playing uses `"listen_type": "playing_now"`. Nothing is sent when Now Playing stops.

</TabItem>
</Tabs>

### Headers

Use `headers` to send extra headers with every request, like an API key or token:

```json5
"headers": {
  "Authorization": "Bearer mytoken"
}
```

Header values are partially redacted when logged on startup.

### Health and Auth Checks

Optional URLs Multi-Scrobbler calls with a `GET` request (including your `headers`) when the Client starts:

* `endpointHealth` (or ENV `BLACKBOX_ENDPOINT_HEALTH`) checks that your service is reachable and ready
* `endpointAuth` checks that your `headers` are accepted
  * <Badge text="Note" size="small" variant="note" /> There is no ENV equivalent for this due to the potential complexity of headers. You will need to use File/AIO config if you need auth + headers.

A `2xx` response is treated as success. If these are not set, Multi-Scrobbler skips the check and assumes your endpoint is ready.
