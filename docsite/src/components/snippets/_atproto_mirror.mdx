<DetailsAdmo summary="MS Mirrors Your PDS History">

ATProto-based Clients, like {props.name}, cannot query an API to get scrobbles with timestamps in an arbitrary time range the same way most other Clients can. This prevents MS from being able to check for duplicate scrobbles downstream, "on-demand."

<details>

<summary>Why?</summary>

Most other scrobble services allow fetching an arbitrary time range for scrobble data. MS uses this functionality to check for duplicates (in addition to checking its own databse of sent scrobbles).

However, the ATProto PDS API specification only allows querying your repository *sequentially* and with offsets that are not related to the timestamp of your scrobbles.

The only way search for scrobbles records at a specific time in your account is to either a) sequentially walk every page of your records through the API until we find them or b) download a [**full** export of all data in your repository](https://atproto.com/blog/repo-export) as a CAR file, parse it fully, and then search that data.

</details>

In order to compensate for this missing query functionality, the {props.name} Client keeps a **copy** of your scrobbles in the Multi-Scrobbler database. This copy is a **locked** [Mirror](/transfer/overview) of your account's scrobbles, parsed from your [**full** account history (CAR) file.](https://atproto.com/blog/repo-export)

Before the Client scrobbles, it compares the Play against the Mirror to find duplicates. You cannot clean up or delete this Mirror.

By default, the Mirror has only the scrobbles of the last 30 days. The Client copies them from your repository's CAR file when it starts for the first time.


<DetailsAdmo summary="Older Plays">

<summary>Older Plays</summary>

When the Client gets a Play that is older than the Mirror, it copies the scrobbles of that time from your repository's CAR file. This copy is a pass. During the pass:

* The Play stays in the queue. Its history shows that it waits for the pass.
* The Client continues to send other Plays.
* Other older Plays that are queued at the same time use the same pass.

After the pass, the Client compares the Play against the Mirror and sends it. Multi-Scrobbler keeps the downloaded repository for 1 hour, and other passes in that hour use it again.

Once a day, Multi-Scrobbler removes the scrobbles that are older than 30 days from the Mirror. It does not remove scrobbles that queued Plays or running Exports need.

</DetailsAdmo>

<DetailsAdmo type="tip" summary="Keeping All History">

To keep *all* your scrobbles in the Mirror, rather than only 30 days, set `keepAllHistory` to `true` in the `options` of the Client configuration. With ENV, set <code>{props.env}_KEEP_ALL_HISTORY=true</code>.

```json5 label="file" title="Example File or AIO Config"
[
  {
    // ...your Client configuration
    "configureAs": "client",
    "data": { /* ... */ },
    // [!code focus:3]
    "options": {
      "keepAllHistory": true
    }
  }
]
```

With this option, the Client copies your full history at the next start and never removes scrobbles from the Mirror. Older Plays do not wait for a pass. The database uses more disk space, about a few hundred bytes for each scrobble.

This is a good option to enable if you are planning on [Exporting](/transfer/overview) scrobbles to {props.name} that cover a large date range.

If you turn the option off, the daily cleanup removes the scrobbles that are older than 30 days. The database file does not get smaller by itself. To make it smaller, see [Reclaiming Disk Space](/configuration#reclaiming-disk-space).

</DetailsAdmo>
